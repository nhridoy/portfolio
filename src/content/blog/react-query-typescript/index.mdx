# Efficient Data Fetching in React with React Query and TypeScript

Fetching data and keeping it in sync across components can be a pain, especially when you need type safety. In this post we’ll set up **React Query** (now called **TanStack Query**) in a TypeScript‑based React app, showing how to get typed data, caching, and background refetches with minimal boilerplate.

## Why React Query?
- **Automatic caching** – no manual Redux store needed.
- **Stale‑while‑revalidate** – keep UI fast while data updates behind the scenes.
- **Built‑in retries** – recover from transient network errors.
- **Type‑safe hooks** – thanks to generics, you get full IntelliSense.

## Prerequisites
- A Next.js + Nextra project (already present).
- `react@18` and `react-dom@18`.
- Node ≥ 18.

## Installation
```bash
npm install @tanstack/react-query @tanstack/react-query-devtools
# or with pnpm
pnpm add @tanstack/react-query @tanstack/react-query-devtools
```

## Step‑by‑Step Setup

<Steps>
#### Step 1: Wrap your app with `QueryClientProvider`
Create a client once (e.g., in `src/app/providers.tsx`) and provide it at the root.

```tsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';

const queryClient = new QueryClient();

export default function Providers({ children }: { children: React.ReactNode }) {
  return (
    <QueryClientProvider client={queryClient}>
      {children}
      <ReactQueryDevtools initialIsOpen={false} />
    </QueryClientProvider>
  );
}
```

Add `Providers` to your layout (e.g., `src/app/layout.tsx`).

#### Step 2: Create a typed fetcher
```ts
export interface Post {
  id: number;
  title: string;
  body: string;
  userId: number;
}

export const fetchPosts = async (): Promise<Post[]> => {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  if (!res.ok) throw new Error('Network response was not ok');
  return res.json();
};
```

#### Step 3: Use `useQuery` in a component
```tsx
import { useQuery } from '@tanstack/react-query';
import { fetchPosts, Post } from '../lib/api';

export function PostsList() {
  const { data, error, isLoading } = useQuery<Post[], Error>({
    queryKey: ['posts'],
    queryFn: fetchPosts,
  });

  if (isLoading) return <p>Loading posts…</p>;
  if (error) return <p>Error: {error.message}</p>;

  return (
    <ul>
      {data!.map((post) => (
        <li key={post.id}>
          <strong>{post.title}</strong>
          <p>{post.body}</p>
        </li>
      ))}
    </ul>
  );
}
```

#### Step 4: Call the component from a page
Create `src/app/react-query-demo/page.tsx` (or any route) and render `<PostsList />`.

```tsx
import { PostsList } from '../../components/PostsList';

export default function Page() {
  return (
    <section>
      <h1>React Query Demo</h1>
      <PostsList />
    </section>
  );
}
```

#### Step 5: Optional – Pagination with `useInfiniteQuery`
```tsx
import { useInfiniteQuery } from '@tanstack/react-query';

// fetch page
const fetchPostsPage = async ({ pageParam = 1 }) => {
  const res = await fetch(`https://example.com/api/posts?page=${pageParam}`);
  return res.json();
};

const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({
  queryKey: ['posts', 'infinite'],
  queryFn: fetchPostsPage,
  getNextPageParam: (lastPage) => lastPage.nextPage ?? false,
});
```
</Steps>

> <Callout type="info">
> React Query works out of the box with **Next.js** because the library is framework‑agnostic. The only thing you need to remember is to **avoid using `window` during SSR** – keep data fetching inside the hook, not in `getStaticProps`.
> </Callout>

## Bonus: Type‑Safe Query Keys
You can centralise your query keys to avoid typos:

```ts
export const queryKeys = {
  posts: ['posts'] as const,
  post: (id: number) => ['post', id] as const,
};
```

Then use them like:
```tsx
useQuery({ queryKey: queryKeys.posts, queryFn: fetchPosts })
```
