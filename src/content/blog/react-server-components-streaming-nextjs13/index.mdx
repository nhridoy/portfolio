# React Server Components Meet Streaming: A Real‑World Example in Next.js 13

The latest **React Server Components (RSC)** release finally ships with built‑in **streaming** support in Next.js 13.  
What does that mean for us? A page can now start rendering on the client *as soon as the first chunk of data arrives* from the server, without waiting for the entire component tree to finish fetching. The result is a snappier, perceived‑fast load—exactly what users expect from modern web apps.

## Why streaming matters

Traditional SSR (or even static generation) sends a fully‑rendered HTML blob to the browser. If a component deep in the tree performs a slow fetch, the whole page is delayed. With streaming:

1. **The server streams HTML chunks** as each component resolves.
2. **The browser progressively hydrates** those chunks, showing UI incrementally.
3. **Network idle time drops** because the browser can start fetching client‑side code earlier.

The impact is most noticeable on data‑heavy pages: dashboards, product catalogs, or any page that mixes fast static sections with slower remote calls.

## A minimal Next.js 13 example

Below is a tiny Next‑app that demonstrates the pattern.  
Create `app/page.tsx` (the default route) and two server components: `Header` (instant) and `HeavyData` (simulated delay).

```tsx
// app/page.tsx
import Header from "./Header";
import HeavyData from "./HeavyData";

export default async function Page() {
  return (
    <>
      <Header />
      {/* HeavyData will stream in once its promise resolves */}
      <HeavyData />
    </>
  );
}
```

```tsx
// app/Header.tsx (Server Component, instant)
export default function Header() {
  return <h1>📊 Dashboard Overview</h1>;
}
```

```tsx
// app/HeavyData.tsx (Server Component, streamed)
import { Suspense } from "react";

async function fetchStats() {
  // Simulate a slow API; replace with real fetch in production
  await new Promise((r) => setTimeout(r, 2500));
  return { users: 1_254, revenue: "$23.1k" };
}

export default function HeavyData() {
  return (
    <Suspense fallback={<p>Loading stats…</p>}>
      <Stats />
    </Suspense>
  );
}

async function Stats() {
  const { users, revenue } = await fetchStats();
  return (
    <section>
      <p>👥 Active users: {users}</p>
      <p>💰 Revenue today: {revenue}</p>
    </section>
  );
}
```

### What happens under the hood?

- **`Header`** renders immediately and streams its `<h1>` tag to the client.
- The **`Suspense`** boundary shows a fallback (`Loading stats…`) while `fetchStats()` resolves.
- Once the promise settles, Next.js streams the `<section>` with the real data.

No extra client‑side JS is required for the data fetch; everything stays on the server, preserving the small bundle size that Next.js 13 championed.

## Tips for production

| Tip | Reason |
|-----|--------|
| **Keep fetches short** | Even with streaming, a 30‑second API call blocks its own chunk. |
| **Use `Suspense` boundaries wisely** | Separate fast UI from slow data to avoid unnecessary placeholders. |
| **Leverage `cache()`** | Memoize frequent calls; the server can serve cached streams instantly. |
| **Monitor streaming** | Chrome DevTools > Network → “Preserve log” shows the incremental response. |

## TL;DR

React Server Components with streaming let you ship instantly visible UI while the server continues to render slower parts, giving developers a simple way to improve perceived performance in Next.js 13.
